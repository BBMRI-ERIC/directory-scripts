# Survey Agent Instructions

These rules apply to the root survey CLI, its SO2/MuCP helpers, survey mappings and survey tests. Read [DEVELOPMENT.md](DEVELOPMENT.md) for full contracts and [root guardrails](../../AGENTS.md) for shared rules.

- `survey-so2-directory.py` is a one-off analysis CLI for the SO2 Datafication survey, but it must still reuse `directory.py`, shared auth/schema CLI conventions, and qcheck-style `EntityFixProposal` export semantics. Keep the survey-to-Directory mapping in editable JSON (`survey-mappings/so2_2025_directory_mapping.json`), resolve respondents conservatively (explicit biobank/collection IDs first, then certain/approximate institution-name mapping), and do not report all Directory biobanks missing from the survey. WSI consistency is necessarily indirect until the Directory has a dedicated WSI field: analyze only generic imaging metadata and unstructured text, and keep survey-driven update proposals limited to supported structured biobank/collection fields rather than free-text rewrites.
- Survey respondent matching should normalize bare biobank IDs to canonical `bbmri-eric:ID:...` form, keep invalid explicit IDs as diagnostic notes instead of aborting resolution, and use institution aliases/acronyms plus accent-insensitive typo-tolerant matching on names and IDs (for example `CHUV` -> `bbmri-eric:ID:CH_CHUV`) before giving up as missing.
- `survey-so2-directory.py` also relies on an editable survey-question to strategic-objective mapping JSON (`survey-mappings/so2_2025_question_to_strategic_objectives.json`) derived from the SO2 work-programme PPTX; keep strategic-objective tags in the findings JSON so the PDF can aggregate findings per SO and per SO/biobank without re-reading the survey workbook.
- Only `survey-so2-directory.py describe` and `render-descriptive-report` are Directory-free: they must not load Directory data, request credentials, use entity-resolution/objective mappings, or create findings/update plans. Keep `analyze`, `render-report`, and `export-update-plan` on their existing shared Directory/mapping paths.
- SO2 `describe` merges repeated submissions only by explicit valid biobank IDs or reviewed offline identity mappings. Preserve every original response and flag conflicts; never merge by similar institution names alone. Unresolved identities remain separate analytical observations. Report the merge protocol/counts/groups in Responses Summary after Abbreviations; see DEVELOPMENT.md. Generated descriptive JSON, TeX, PDFs, and chart artifacts are sensitive output.
- Keep raw survey exports/archives, source-bound identity/quantity reviews, private scoring-reference data and generated survey artifacts ignored/local. Share only data-free form manifests, scoring definitions and invented fixtures; see `DEVELOPMENT.md` for portable defaults and optional local replay.
- `survey-so2-directory.py export-eus-form-json` is the only path that decodes the matching EUSurvey archive. `describe` requires its generated JSON form manifest, derives response type, requiredness, dependencies, and matrix title/row fields from it, and rejects missing or incompatible schema mappings. Never infer form semantics from answers or wording. Descriptive TeX uses `scrartcl` with `\KOMAoptions{parskip=half}` and zero paragraph indent; use `\par`/`\vspace` for ordinary spacing, never `\\`.
- SO2 descriptive schemas must validate applicability values against their referenced structured parent categories and mutually exclusive values against their declaring question. Free-text `parent_context_values` must list only selections that semantically enable that child field; retain both semantic and raw parent evidence in JSON and diagnose nonmatching parent selections without dropping substantive text. Default reports omit parent context entirely; `--include-parent-context` must show only complete raw parent answers, never the semantically filtered subset. Every function in `so2_descriptive_report.py` and `survey-so2-directory.py` must document the semantics of each input parameter and return value; keep their AST-backed documentation regression green. Preserve contradictory selections in counts and emit diagnostics rather than silently dropping them.
- SO2 descriptive PDF rendering invokes `xelatex` twice to resolve the table of contents and must fail rather than leave a partial PDF when compilation, writes, or assets are unavailable. Keep free-text tables reader-oriented: two-letter country code, institution, fixed parent question(s) in the header with same-order values in cells, and no source-row column. Long bar charts must consume the printable text height before pagination with a shared zero-based count scale; pie labels must remain inside the pie's vertical extent and near their slice centers. Published TeX is self-contained. Descriptive file outputs are new-file only by default; `describe --overwrite` may deliberately replace its JSON, TeX, PDF and chart directory after successful staging. `--output-chart-dir` is new-or-empty by default and contains standalone vector chart PDFs from the same PGF/TikZ source. Publish through target-directory sibling stages so cross-device targets remain atomic, and keep output targets distinct from inputs and one another.
- `survey-so2-directory.py` PDF output should keep repetitive methodology details out of the main sections: use a clickable table of contents, keep one appendix entry per finding type, make report tables link to that appendix, keep consistent findings terse, and show compact concrete `Survey=...; Directory=...` values only for non-consistent findings. Prefer `latexmk -pdfxe` when available and keep mapping/entity identifiers line-breakable in TeX so report tables remain readable.
- Technology-modality UpSet extraction in `survey-so2-directory.py` should treat the required survey `Other` checkbox as non-informative unless the `Technologies` free-text field contains positive content. Keep true NGS on the dedicated sequencing field, infer `Genotyping / panels` only from clearly genotyping/panel-like `Technologies` text under `Other`, and do not silently fold pure epigenomics-only wording into that bucket.
- The R technology-matrix plot generated by `survey-so2-directory.py` should label rows as `survey_row (CC): institution`, keep a white background, and sort countries ascending with `A...` countries rendered at the top of the plot; remember ggplot places the first factor levels at the bottom unless the levels are reversed explicitly.
