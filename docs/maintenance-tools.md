# Maintenance and synchronization tools

These tools can modify Directory staging data or synchronize external systems.
Use explicit schemas, inspect dry-runs, and keep backups. The aggregated public
`ERIC` schema should not normally be edited directly.

## Directory table modifier

`directory-tables-modifier.py` imports, deletes, exports, or synchronizes one
table. Exactly one action is required. The target staging schema is always
explicit with `-s/--schema`, and import/delete/export/sync requires
`-T/--table`.

Safety controls:

- `-n/--dry-run` previews changes without writing
- data-changing operations require confirmation unless `-f/--force` is used
- explicitly targeting `ERIC` requires an additional confirmation
- `--export-on-delete FILE` backs up rows selected for deletion
- sync creates a temporary full-column backup and attempts rollback if import
  fails, but the server operation is not atomic
- filters apply to IDs (`-R/--id-regex`) and collections
  (`-C/--collection-id`)
- CSV/TSV is detected from the extension; `-F` and `-S` override format and
  separator

Preview and then delete facts for one collection without an input file:

```bash
./directory-tables-modifier.py -s BBMRI-EU -T CollectionFacts \
  -x --delete-filter-only \
  -C bbmri-eric:ID:EU_EXAMPLE:collection:COLLECTION -n -v

./directory-tables-modifier.py -s BBMRI-EU -T CollectionFacts \
  -x --delete-filter-only \
  -C bbmri-eric:ID:EU_EXAMPLE:collection:COLLECTION -v
```

Import and export facts:

```bash
./directory-tables-modifier.py -s BBMRI-EU -T CollectionFacts \
  -i facts.tsv -N BBMRI-EU -f

./directory-tables-modifier.py -s BBMRI-EU -T CollectionFacts \
  -e facts-current.tsv \
  -C bbmri-eric:ID:EU_EXAMPLE:collection:COLLECTION
```

Synchronize a table after reviewing the dry-run:

```bash
./directory-tables-modifier.py -s BBMRI-EU -T CollectionFacts \
  -y facts.tsv -n --export-on-delete facts-backup.tsv
```

For `CollectionFacts`, `-k/--k-donors` and `-K/--k-samples` skip imported
rows where `0 < count < k`; zero-valued rows remain. The recommended baseline
for publicly exposed aggregated donor data is `k=10`, unless a documented
policy justifies another threshold.

## Collection descriptor updater

`collection-factsheet-descriptor-updater.py` reads one collection and its facts
from public `ERIC`, derives collection-level descriptor changes, and writes only
to the explicitly selected staging schema.

```bash
python3 collection-factsheet-descriptor-updater.py \
  -c bbmri-eric:ID:EU_EXAMPLE:collection:COLLECTION \
  -s BBMRI-EU -n -v
```

By default it appends missing multi-value descriptors. Use
`--replace-existing` only when removal/replacement is intended. Sample and donor
totals can be updated from one all-star row without that option. `NAV` material
is not propagated when richer material values exist, ICD hierarchy coverage is
respected, and age proposals span the represented minimum to maximum when one
consistent unit is available.

The tool confirms collection-ID/staging-schema mismatches unless `--force` is
used, and fails if the target collection is absent from that schema.

## QC updater

`qcheck-updater.py` applies structured proposals generated by `data-check.py`.
The full operator workflow and safety constraints are documented in
[Data quality checks](data-quality.md#qc-derived-updates).

## External synchronization

`importer-ecrin-mdr.py` converts ECRIN MDR study mappings into Directory
`Studies`, `AlsoKnownIn`, and collection-study relationship records. It can
generate node-grouped CSV files or upload them when explicitly configured.
Inspect `python3 importer-ecrin-mdr.py --help` before use because it accesses an
external MDR service and can write Directory data.

`sync_directory_with_fdp.py` is a legacy synchronization path from Directory
biobanks and collections to an FDP/DCAT Molgenis model. It targets external
systems and should be reviewed against their current schemas and authentication
requirements before use.
